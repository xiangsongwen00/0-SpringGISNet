# PostgreSQL/PostGIS 数据库部署与迁移指南

> 当前工程面向 PostgreSQL 17 + PostGIS 3.5。最后核对：2026-10-15。示例中的密码必须替换，严禁把真实密码提交到 Git。

## 1. 当前数据库职责

数据库保存账户认证、用户同意记录、终端、授权码、安全问题、会话/审计，以及位置设置、当前位置、轨迹段和位置分享。客户端不能直接连接数据库，必须经过 Python API 的权限校验。

迁移文件按顺序位于 `migrations/`：

```text
001_initial.sql
002_user_consents.sql
003_terminals.sql
004_authorization_codes.sql
005_security_answers.sql
006_location_tracking.sql
```

`schema_migrations` 记录已经应用的版本；不要手工把 SQL 文件标记为完成。

## 2. Docker/PostGIS 初始化

现有 PostGIS 容器可继续使用。新建时可参考：

```bash
docker network create springgis
docker run -d \
  --name springgis-postgres \
  --network springgis \
  --restart unless-stopped \
  -e POSTGRES_DB=springgis \
  -e POSTGRES_USER=springgis \
  -e POSTGRES_PASSWORD='替换为强密码' \
  -v /opt/springgis/postgres:/var/lib/postgresql/data \
  postgis/postgis:17-3.5-alpine
```

验证：

```bash
docker exec springgis-postgres pg_isready -U springgis -d springgis
docker exec -it springgis-postgres psql -U springgis -d springgis -c 'SELECT version();'
docker exec -it springgis-postgres psql -U springgis -d springgis -c 'CREATE EXTENSION IF NOT EXISTS postgis; SELECT PostGIS_Version();'
```

如果使用现有容器 `1Panel-postgresql-be7Q`，把示例容器名替换掉即可。不要删除或重新创建持久卷。

## 3. postgis.json

文件位置：`0-pythonServer/data/postgis.json`。

```json
{
  "host": "springgis-postgres",
  "port": 5432,
  "user": "springgis",
  "password": "替换为强密码",
  "database": "springgis"
}
```

代码读取 `host`、`port`、`user`、`password`、`database`（也兼容 `dbname`）。`$schema` 不是 PostgreSQL schema 配置，当前代码不会读取它；应用默认使用数据库账号的 `search_path`，通常是 `public`。

连接地址选择：

| Python 所在位置 | 连接目标 | host | port |
| --- | --- | --- | ---: |
| 与 PostGIS 同 Docker 网络 | PostGIS | 容器服务名/网络别名 | 5432 |
| 与 PgBouncer 同 Docker 网络 | PgBouncer | PgBouncer 服务名 | 5432 |
| 宿主机进程 | PostGIS 映射 | `127.0.0.1` | 5432 |
| 宿主机进程 | PgBouncer 映射 | `127.0.0.1` | 6432 |
| Python 容器经宿主机映射 | 宿主机网关/可达地址 | 实际地址 | 5432 或 6432 |

容器之间不要写 `127.0.0.1`，除非两个进程确实运行在同一个容器中。

## 4. PgBouncer

可以连接 PgBouncer，不需要修改 Python 业务代码；对 SQLAlchemy/psycopg2 来说它仍是 PostgreSQL 端点。

推荐做法：

- API 的日常短连接/并发连接走 PgBouncer。
- 迁移、备份和数据库管理优先直连 PostgreSQL，减少连接池模式对 DDL 的影响。
- 同网络使用 `pgbouncer:5432`；从宿主机使用当前映射 `127.0.0.1:6432`。
- 确保 PgBouncer 的用户密码、目标数据库和认证方式与 PostgreSQL 一致。

迁移时可临时直连而不改文件：

```bash
export SPRINGGIS_DATABASE_URL='postgresql+psycopg2://springgis:URL编码后的密码@springgis-postgres:5432/springgis'
python index.py --migrate
unset SPRINGGIS_DATABASE_URL
```

URL 中的 `@`、`:`、`/` 等特殊字符必须编码。更安全的做法是由 1Panel/Docker Secret 注入变量，避免命令进入 shell 历史。

## 5. 执行迁移

首选方式，在后端目录执行：

```powershell
cd E:\0-SpringGISNet\0-pythonServer
D:\condamini\python.exe index.py --migrate
```

Linux/容器：

```bash
cd /app/0-pythonServer
python index.py --migrate
```

兼容测试入口只能从仓库根目录运行：

```powershell
cd E:\0-SpringGISNet
D:\condamini\python.exe 0-testpy\apply_migration.py
```

过去出现 `0-pythonServer\0-testpy\apply_migration.py` 不存在，是因为已经 `cd 0-pythonServer` 后又使用了仓库根目录相对路径。避免此错误的最简单办法是始终用 `index.py --migrate`。

迁移具有版本记录，可以重复运行；已应用版本应显示跳过，新版本显示应用成功。失败时不要手工修改业务表，保留完整错误日志并先恢复连接/权限问题。

## 6. 迁移前备份

在数据库容器内创建 custom 格式备份：

```bash
mkdir -p /opt/springgis/backups
docker exec springgis-postgres pg_dump -U springgis -d springgis -Fc > /opt/springgis/backups/springgis-before-migration.dump
test -s /opt/springgis/backups/springgis-before-migration.dump
```

现有容器名为 `1Panel-postgresql-be7Q` 时替换容器名。备份文件必须再复制到异机/对象存储；只和数据库放在同一磁盘不算完整备份。

恢复会覆盖/合并数据库对象，必须在维护窗口、确认目标库并停止写入后执行：

```bash
pg_restore --list springgis-before-migration.dump | head
docker exec -i springgis-postgres pg_restore -U springgis -d springgis --clean --if-exists < springgis-before-migration.dump
```

不要在生产库直接试恢复；先恢复到临时数据库验证文件可用。

## 7. 结构与连接验证

仓库根目录提供只读诊断：

```powershell
cd E:\0-SpringGISNet
D:\condamini\python.exe 0-testpy\diagnose_remote_db.py
```

它使用与后端相同的数据库配置，输出连接端点、表和迁移版本，不写业务数据。也可直接查询：

```bash
docker exec -it springgis-postgres psql -U springgis -d springgis -c 'TABLE schema_migrations;'
docker exec -it springgis-postgres psql -U springgis -d springgis -c '\dt'
docker exec -it springgis-postgres psql -U springgis -d springgis -c 'SELECT PostGIS_Version();'
```

位置模块至少应有 `location_settings`、`current_locations`、`track_segments`、`location_shares`。

## 8. 轨迹数据说明

- `current_locations` 保存用户当前最新位置，便于实时查询。
- `track_segments` 按用户、终端、日期和时间索引组织轨迹段，每段最多聚合一定数量的点。
- `location_shares` 保存主动授予的实时或历史共享权限。
- API 将历史查询/分享限制在三天窗口内；这不等于数据库自动删除三天前数据。

当前没有文档可证明已经配置自动清理任务，因此不要假设旧轨迹会自动删除。若今后要实施保留期，应新增明确的迁移/定时任务、审计和备份策略，而不是直接在生产库手工 `DELETE`。

## 9. 故障排查

### password authentication failed

核对 PostgreSQL 用户、密码、PgBouncer 用户列表和目标数据库。修改密码后同步更新 secret，并重启连接池/API。

### connection refused / timeout

```bash
docker inspect python312 --format '{{json .NetworkSettings.Networks}}'
docker inspect 1Panel-postgresql-be7Q --format '{{json .NetworkSettings.Networks}}'
docker exec python312 getent hosts 1Panel-postgresql-be7Q
```

确认两个容器共享网络、数据库监听、端口选择正确。容器内的 `127.0.0.1:5432` 通常是错误地址。

### relation does not exist / column does not exist

代码已更新但迁移未执行或执行到了另一数据库。查询 `current_database()`、`current_user` 和 `schema_migrations`，再运行 `index.py --migrate`。

### PgBouncer 可连但迁移失败

临时用 `SPRINGGIS_DATABASE_URL` 直连 PostgreSQL 执行迁移，运行时再恢复 PgBouncer。

## 10. 安全底线

- 生产 5432/6432 不对公网开放，只允许 Docker 网络或可信管理网。
- `postgis.json` 权限限制到 API 运行账号，不上传 Git。
- 定期轮换密码；数据库账号不使用超级用户。
- 备份加密、异地保存并定期演练恢复。
- SQL 日志、错误截图和支持工单中隐藏密码、Token、用户安全答案和精确轨迹。
