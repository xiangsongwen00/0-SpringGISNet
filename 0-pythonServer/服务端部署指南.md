# Python 服务端部署指南

> FastAPI 服务固定监听 `8080`。最后核对：2026-10-15。数据库部署和迁移见 [数据库部署与迁移指南.md](数据库部署与迁移指南.md)。

## 1. 项目边界与目录

- 入口：`index.py`
- 配置：`env.ini`
- API：`app/api/v1/`
- 业务服务：`app/services/`
- 模型：`app/models.py`
- 迁移：`migrations/`
- 敏感运行数据：`data/postgis.json`、`data/server_secret.key`
- 接口文档：运行后的 `/docs`，静态说明见根目录 `API.md`

服务端不读取 PC 的 `config/pc.env.json`，也不读取 APK 的配置。

## 2. 本机 Windows 启动

推荐使用明确的 Python 路径，避免 Conda 环境混淆：

```powershell
cd E:\0-SpringGISNet\0-pythonServer
D:\condamini\python.exe -m pip install -r requirements.txt
D:\condamini\python.exe index.py --migrate
D:\condamini\python.exe index.py
```

验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8080/api/v1/health
```

Swagger：`http://127.0.0.1:8080/docs`。

开发时可使用 `python index.py --reload`。`--host` 和 `--port` 只用于临时诊断，正式配置仍以 `env.ini` 为准，端口保持 8080。

## 3. env.ini 字段

```ini
[server]
host = 0.0.0.0
port = 8080
environment = development
access_log = false

[database]
config_path = data/postgis.json

[security]
access_token_minutes = 15
refresh_token_days = 30
secret_key_file = data/server_secret.key

[cors]
origins = http://8.137.36.114:8000

[geocoding]
amap_web_service_key =
```

- `host=0.0.0.0` 让容器/局域网可以访问；这不是客户端请求地址。
- `port=8080` 是固定服务端口。
- `config_path` 相对 `0-pythonServer` 解析。
- `server_secret.key` 首次启动可自动生成，但容器更新时必须持久化；丢失会使现有会话失效。
- 当前 PC 正式站点运行在 `http://8.137.36.114:8000`，并直接访问 `8080` API，因此 `origins` 应精确包含该 PC 来源；原生 APK 不使用浏览器 CORS。
- 高德 Web 服务 Key 属于服务端秘密，只放服务器，不打入 PC/APK。默认从被 Git 忽略的 `data/amap_web_service.key` 读取，也可以通过 `SPRINGGIS_AMAP_WEB_SERVICE_KEY` 注入。

可用环境变量覆盖：

| 变量 | 用途 |
| --- | --- |
| `SPRINGGIS_ENV_FILE` | 指向另一份 ini |
| `SPRINGGIS_DATABASE_CONFIG` | 指向另一份数据库 JSON |
| `SPRINGGIS_DATABASE_URL` | 完整 SQLAlchemy PostgreSQL URL，优先级最高 |
| `SPRINGGIS_SECRET_KEY` | 直接注入签名密钥 |
| `SPRINGGIS_API_HOST` / `SPRINGGIS_API_PORT` | 临时覆盖监听地址/端口 |
| `SPRINGGIS_ENVIRONMENT` | 环境名 |
| `SPRINGGIS_ACCESS_LOG` | `true/false` |
| `SPRINGGIS_ACCESS_TOKEN_MINUTES` | Access Token 分钟数 |
| `SPRINGGIS_REFRESH_TOKEN_DAYS` | Refresh Token 天数 |
| `SPRINGGIS_CORS_ORIGINS` | 逗号分隔的精确浏览器来源 |
| `SPRINGGIS_AMAP_WEB_SERVICE_KEY` | 高德逆地理编码服务端 Key |

## 4. Docker/1Panel 部署原则

当前服务器结构可保持：Python 容器发布 `8080:8080`，PostGIS 容器使用 5432，PgBouncer 宿主机使用 6432。推荐把三者加入同一个用户自定义 Docker 网络，通过容器名解析，而不是互相使用公网 IP。

关键规则：

- Python 容器中的 `127.0.0.1` 是 Python 容器自身，不能连接另一个 PostgreSQL 容器。
- 同一 Docker 网络直连 PostgreSQL：数据库 host 写 PostgreSQL 服务名/容器网络别名，port 写 `5432`。
- 同一网络连 PgBouncer：host 写 PgBouncer 服务名，port 写其容器内部端口 `5432`。
- 通过宿主机映射连 PgBouncer：host 写 Docker 宿主机可达地址，port 写 `6432`。
- 不建议容器用公网 `8.137.36.114:5432` 绕回本机数据库。

一个可参考的 Compose 片段如下；密码、卷目录和网络名必须按服务器实际值替换：

```yaml
services:
  api:
    image: python:3.12.12
    working_dir: /0-myserver/0-pythonServer
    command: ["bash", "/run.sh"]
    ports:
      - "8080:8080"
    volumes:
      - /opt/springgis/repo:/app
      - /opt/springgis/secrets/postgis.json:/0-myserver/0-pythonServer/data/postgis.json:ro
      - /opt/springgis/secrets/server_secret.key:/0-myserver/0-pythonServer/data/server_secret.key
      - /opt/springgis/run.sh:/run.sh:ro
    networks: [springgis]
    restart: unless-stopped

networks:
  springgis:
    external: true
```

`/run.sh` 的最小逻辑：

```bash
#!/usr/bin/env bash
set -euo pipefail
cd /0-myserver/0-pythonServer
python -m pip install --no-cache-dir -r requirements.txt
python index.py --migrate
exec python index.py
```

迁移放在启动之前且使用 `exec` 启动主进程，容器才能正确接收停止信号。正式环境更推荐提前构建包含依赖的专用镜像，减少每次重启联网安装的风险。

## 5. 首次上线

1. 上传代码，但不要覆盖服务器现有 secret。
2. 挂载或创建 `data/postgis.json`。
3. 创建持久化 `data/server_secret.key`；若首次自动生成，立刻确认它在宿主机持久卷中。
4. 进入容器安装依赖并迁移：

```bash
docker exec -it python312 bash
cd /0-myserver/0-pythonServer
python -m pip install -r requirements.txt
python index.py --migrate
exit
docker restart python312
```

5. 检查：

```bash
docker ps
docker logs --tail 200 python312
curl -fsS http://127.0.0.1:8080/api/v1/health
```

容器内实际代码目录可能不是 `/app`，应先用 `docker inspect python312` 核对 Mounts 和工作目录，不要盲目复制命令。

## 6. 日常更新

```text
数据库备份 → 上传代码 → 安装新增依赖 → 执行迁移 → 重启 API → health → 核心接口冒烟测试
```

推荐命令：

```bash
docker exec -it python312 bash -lc 'cd /0-myserver/0-pythonServer && python -m pip install -r requirements.txt && python index.py --migrate'
docker restart python312
docker logs --tail 200 python312
curl -fsS http://127.0.0.1:8080/api/v1/health
```

如果目录不同，先改成服务器的真实挂载路径。不要在未备份数据库时尝试手工回滚迁移。

## 7. OpenResty 与网络安全

当前约定是 PC 在 `8000`、API 在 `8080`，所以服务器需要开放这两个端口。未来切换到域名 HTTPS 后，推荐只公开 80/443，并由 OpenResty 代理内部 API；届时必须同时更新 PC 的 `productionBaseUrl`、APK 的 `androidBaseUrl` 和后端 CORS。

- 云安全组和系统防火墙关闭公网 5432、6432。
- 在当前 IP + 独立端口方案下，8080 必须允许 PC 浏览器和 APK 访问；切换 HTTPS 反向代理后再限制为本机/可信管理网。
- 数据库账号禁止超级用户权限，secret 文件仅服务账号可读。
- 生产日志不要记录密码、Token、公钥原文、精确位置请求体。

## 8. CORS 正确配置

当前独立端口方案必须填写 PC 页面来源：

```ini
[cors]
origins = http://8.137.36.114:8000
```

来源只能是“协议 + 主机 + 可选端口”，不能带 `/api/v1`，不能写 `*`。修改后重启 API。`http://8.137.36.114:8080` 是 API 地址，不是 PC 页面来源，因此 CORS 中应填写 `http://8.137.36.114:8000`。

## 9. 8080 启动失败

Windows 的 `[WinError 10013]` 可能是端口占用、系统保留端口或安全软件拦截：

```powershell
Get-NetTCPConnection -LocalPort 8080 -ErrorAction SilentlyContinue
netsh interface ipv4 show excludedportrange protocol=tcp
```

若有旧进程，确认身份后停止旧服务；若 8080 落入排除范围，查明 Hyper-V/WSL/端口代理来源并调整系统服务。项目正式端口仍保持 8080，不要把临时 `--port 18081` 当成解决方案。

Linux/Docker：

```bash
ss -lntp | grep ':8080'
docker ps --filter publish=8080
```

## 10. 500/404/422 排查

- 500：看 `docker logs -f python312`；验证数据库 DNS、端口、密码和迁移。
- 404：确认 `/api/v1` 前缀；确认服务器运行的是新代码且路由已挂载。
- 422：按根目录 `API.md` 修正 JSON 字段；FastAPI 已收到请求，通常不是网络问题。
- health 也失败：先处理数据库，因为 health 会执行数据库检查。
- APK 能联网但接口 Not Found：检查 `androidBaseUrl` 末尾是否有 `/api/v1`，并重新打包安装新 APK。

## 11. 发布验收

```bash
docker ps
docker logs --tail 200 python312
curl -i http://127.0.0.1:8080/api/v1/health
curl -I http://127.0.0.1:8080/docs
```

随后从公网 HTTPS 域名测试 health、登录、终端绑定和位置接口。不要只看容器 `Up`；应用可能已启动但数据库请求仍失败。
